# ReDay v2 — รีเซ็ตวันนี้

เว็บแอปที่สร้างจากเอกสาร *ReDay v2 — Full Product Spec* ช่วยตั้งวันใหม่จากเวลาตื่นจริงของวันนี้ ครอบคลุมสี่เสา **นอน / กิน / งาน / ห้อง** ภาษาไทยทั้งหมด เวลาเป็น 24 ชม. (`02:30 น.`) ไม่มี AM/PM

## เปิดใช้งาน

- **เปิดจากเว็บ:** <https://paratakorncsc13-a11y.github.io/Reday-pj/> (deploy อัตโนมัติด้วย GitHub Pages ทุกครั้งที่ push เข้า `main`)
- **รันในเครื่อง:** ไม่ต้อง build เป็น HTML/CSS/JS ล้วน ดับเบิลคลิก `run.bat` (ใช้ `jwebserver` ของ JDK, Python หรือ Node ตัวใดตัวหนึ่ง) หรือ `npm run serve` แล้วเปิด <http://localhost:5173/>
- ติดตั้งเป็นแอป (PWA) ได้เมื่อเปิดผ่าน `https://` หรือ `http://localhost`
- ใช้โหมดในเครื่องล้วน (ไม่ต่อ Supabase): เปิด `?local=1`

## สถาปัตยกรรมโดยย่อ

```
เบราว์เซอร์ (HTML/CSS/JS ล้วน ไม่มี build)
 ├─ หน้าจอ (js/pages/*)  ──เรียกผ่าน──►  js/store.js  (ข้อมูลในหน่วยความจำ + cache localStorage)
 │                                          │  ▲
 │                      rule engine (js/engine.js, ฟังก์ชันบริสุทธิ์) ทุกหน้าอ่านแผนเดียวกัน
 │                                          ▼  │
 └─────────────────────────────────►  js/remote.js ──► Supabase: Auth + Postgres (RLS ทุกตาราง)
```

- **หน้าจอไม่รอเครือข่าย:** `store.js` ทำงานในหน่วยความจำเหมือนเดิม แล้ว `remote.js` ซิงก์เฉพาะแถวที่เปลี่ยนเบื้องหลัง ถ้าออฟไลน์ข้อมูลยังอยู่และส่งใหม่เอง
- **ความปลอดภัยอยู่ที่ฐานข้อมูล:** `sb_publishable_…` ใน `js/config.js` เป็นคีย์สาธารณะโดยออกแบบ ทุกตารางเปิด RLS ให้สิทธิ์เฉพาะ `authenticated` เฉพาะแถวของตัวเอง `anon` เข้าไม่ได้เลย (ทดสอบด้วยผู้ใช้จำลองสองคนใน `supabase/tests/rls.sql`)
- **สองโหมด:** ออนไลน์ (ค่าตั้งต้น) และในเครื่อง (`?local=1`, ชุดทดสอบ) ใช้ `store.js` ตัวเดียวกัน

### ต่างจากสเปกอย่างไร (ตั้งใจ)

| ในสเปก | ในงานนี้ |
|---|---|
| React + Vite + TypeScript | HTML/CSS/JS ล้วน ไม่มี build (ลดความซับซ้อน รันได้ทันที) |
| Supabase Auth + Postgres + RLS | ทำแล้วจริง (`supabase/migrations/`) |
| ลืมรหัสผ่านทางอีเมล | ทำแล้ว ใช้อีเมลของ Supabase (ส่งได้จำกัดต่อชั่วโมง พอสำหรับสาธิต) โหมดในเครื่องใช้รหัสกู้คืนแทน |
| Web push / LINE / pg_cron | ยังไม่ทำ การเตือนขึ้นเป็นแถบใต้ header เฉพาะตอนเปิดแอป (ตามเฟส A) |
| Turnstile / จำกัดอัตราการสมัคร | ไม่ทำ (งานนี้ไม่เปิดสาธารณะ) ใช้ rate limit ของ Supabase |
| ฟอนต์ self-host | ยังไม่ทำ โหลดจาก Google Fonts (ระบุในนโยบายความเป็นส่วนตัวแล้ว) |
| ซิงก์แก้พร้อมกันหลายเครื่อง | แก้ที่ไหนล่าสุดชนะ ไม่รวมข้อมูล (เพียงพอสำหรับผู้ใช้คนเดียว) |
| คลังข้อความ 30 แบบ, ตั้งเวลาเตือนเอง, นอนหลายช่วง (เฟส C) | ยังไม่ทำ (ตอนนี้ 3 แบบต่อข้อความ ตามเกณฑ์เฟส A) |
| ส่งออก/ลบข้อมูล | ส่งออกเป็น JSON, ลบข้อมูลทั้งหมด, ลบบัญชี (ฟังก์ชัน `delete_my_account` ในฐานข้อมูล), ถอนความยินยอม |

### ข้อจำกัดที่ควรรู้ก่อนใช้งานจริง

- นโยบายความเป็นส่วนตัวและข้อกำหนดเป็น **ฉบับร่าง** ยังไม่ผ่านผู้รู้กฎหมาย
- เบอร์สายด่วน 1323 มาจากสเปก ยังไม่ได้ตรวจกับแหล่งจริง
- ยังไม่มีปุ่มนำไฟล์ที่ส่งออกกลับเข้าแอป
- ทดสอบบน Edge และ WebKit (Windows) ยังไม่เคยทดสอบบน iPhone/Android เครื่องจริง

## สิ่งที่ทำแล้ว (เฟส A ครบ + บางส่วนของ B/C)

- **Rule engine ตัวเดียว** `js/engine.js` (`buildDay`, `resetFrom`, `nudgesDue`) เป็นฟังก์ชันบริสุทธิ์ ไม่อ่านนาฬิกา ไม่แตะ DOM ทุกหน้าอ่านจาก `DayPlan` เดียวกัน ข้อความทุกบรรทัดมาจาก plan ตามกฎ R1–R11
- **หน้าจอ:** Landing, สมัคร/เข้าสู่ระบบ, ลืมรหัสผ่าน/ตั้งรหัสใหม่, Onboarding 3 ขั้น, วันนี้, แผน, ห้อง, สรุป, ประวัติ, ฉัน, นโยบายความเป็นส่วนตัว (ฉบับร่าง), ข้อกำหนด (ฉบับร่าง), ช่วยเหลือ (สายด่วน 1323), **คู่มือการใช้งาน** (`#/guide`) พร้อม guards ตามสเปก
- **คู่มือการใช้งาน** (`js/pages/guide.js`): หน้าสาธารณะ อ่านได้ทั้งก่อนและหลังสมัคร มีเริ่มใช้ใน 5 ขั้น, อธิบาย 5 หน้าหลัก, วิธีใช้ 16 ฟีเจอร์ (คืออะไร / วิธีใช้ / ควรรู้) จัดตามสี่เสา, คำศัพท์, แก้ปัญหาเบื้องต้น, ช่องค้นหา และลิงก์ลัด เข้าได้จาก Landing, ช่วยเหลือ, ท้ายหน้า วันนี้ และ ฉัน › คู่มือการใช้งาน เนื้อหาเป็นข้อมูลในไฟล์เดียว แก้ที่ `FEATURES` / `TROUBLE` ได้เลย ชื่อปุ่มในคู่มือเขียนเป็น `[[ชื่อปุ่ม]]` และชุดทดสอบตรวจว่ายังตรงกับปุ่มจริง (แก้ชื่อปุ่มในแอปแล้วคู่มือต้องแก้ตาม ไม่งั้นเทสต์ไม่ผ่าน)
- **ผู้ใช้คุมได้:** พลังงาน (ต่ำ/ปกติ/ดี/ให้ระบบเดา), เพิ่ม–แก้–ลบงานและงานห้อง, เปลี่ยนอันอื่น / เลื่อนไปพรุ่งนี้ / ข้ามวันนี้, มื้อแรก 3 สถานะ (บันทึก / ไม่กินมื้อนี้ / ยังไม่บันทึก), นอนข้ามคืน (ถามเบา ๆ ไม่ขึ้น error), โหมด "วันนี้ขอเบา ๆ", แก้และลบข้อมูลย้อนหลัง
- **TimePicker ของโปรเจกต์** (bottom sheet 00–23 / 00–59, ปุ่มลัดทีละ 5, ±1, ช่องพิมพ์ `HH:mm`) ไม่ใช้ `<input type="time">`; ทุกเวลาแสดงผ่าน `formatTime()`
- **ไทเมอร์งานห้อง** เก็บ `started_at` รีโหลดแล้วนับต่อได้ ครบเวลาไม่ทำเครื่องหมายเสร็จให้เอง สถานะอ่านจาก `chore_completions` ตารางเดียว
- **ความปลอดภัยด้านมื้ออาหาร:** ซ่อนเสา กิน ได้ (onboarding และหน้า ฉัน) → ไม่คำนวณ ไม่เตือน ไม่ใส่ในสรุป; การ์ดชวนคุยเมื่อบันทึกไม่กินมื้อแรก หรือนอนน้อยกว่าเป้ามาก ติดกัน 4 วัน (ไม่เกินสัปดาห์ละครั้ง ปิดได้)
- **เฟส B/C ที่ทำแล้ว:** ซ่อนเสา กิน, การ์ดชวนคุย, ปรับไทเมอร์ 5/10/15 นาที, แก้เหตุผลในสรุป, Quiet hours, PWA (manifest + service worker)
- **ยังไม่ทำ (เฟส C):** ตั้งเวลาเตือนเอง, ปิดเตือน 1 วัน, นอนหลายช่วง/งีบ, ทำไทเมอร์ได้บางส่วน, คลังข้อความ 30 แบบ (ตอนนี้ 3 แบบต่อข้อความ ตามเกณฑ์เฟส A), LLM

## ทดสอบ

เปิด <http://localhost:5173/tests/index.html> ต้องขึ้น "ผ่านทั้งหมด" ครอบคลุม:

- 11 ตัวอย่างทดสอบ engine จากสเปก + กฎ R1–R10 + ฟังก์ชันเวลา
- บั๊ก v1 ทั้ง 10 ข้อที่มีการทดสอบกันกลับมา (เช่น ตื่น 11:20 → มื้อถัดไป 11:50 ทุกหน้า, ไทเมอร์ไม่ทำให้เสร็จเอง, ชื่องานห้องซ้ำถูกปฏิเสธ, งาน onboarding แทนตัวอย่าง)
- สแกนทุกหน้า/แผ่นหา `AM`/`PM`, `<input type="time">`, `null`/`undefined`/`NaN` และคำต้องห้าม (ยังไม่นอนอีกเหรอ, ล้มเหลว, ขี้เกียจ, ข้ามมื้อ)
- เลย์เอาต์จริงใน iframe 390×844 (toast ใต้ header, แท็บกดได้, ไม่ล้นแนวนอนแม้ข้อความยาวไม่มีช่องว่าง, โฟกัส/focus trap ของแผ่น, แถบเตือนหายเมื่อปิดสวิตช์/quiet hours)
- ข้อมูลเสียหาย (JSON เสีย, โครงสร้างผิด, ข้อมูลหาย) และการเปิดหลายแท็บ
- คู่มือการใช้งาน: ครบทุกฟีเจอร์ ค้นหา/ลิงก์ลัด ชื่อปุ่มทุกป้ายตรงกับหน้าจอจริง (เก็บข้อความจากหน้าและแผ่นต่าง ๆ ในหลายสถานการณ์ เช่น ยังไม่บันทึกตื่น, ไทเมอร์เดิน, โหมดขอเบา ๆ, การ์ดชวนคุย) และในแอปจริง 390×844 แถบลิงก์ลัดไม่ทับหัวข้อ ไม่ล้นแนวนอน
- ข้อมูลทดสอบใช้ namespace `reday2test` และ `reday2iframe` แยกจากข้อมูลจริง (ไม่แตะคีย์อื่นของ origin เดียวกัน)

ข้อมูลในเบราว์เซอร์: เปิดหลายแท็บได้ แท็บอื่นเขียนข้อมูลแล้วแท็บนี้โหลดตามให้อัตโนมัติ (ไม่เขียนทับเงียบ ๆ) และถ้าข้อมูลที่เก็บไว้อ่านไม่ได้ แอปจะเริ่มชุดใหม่ให้พร้อมเก็บสำเนาเดิมไว้ที่คีย์ `<คีย์เดิม>.corrupt` และแจ้งผู้ใช้

ไม่มีชุดทดสอบ RLS เพราะยังไม่มี Postgres (ต้องเพิ่มเมื่อย้ายไป Supabase)

### เครื่องมือพัฒนา (ฟรี ใช้เฉพาะตอนพัฒนา ตัวแอปยังไม่มี build step)

ต้องมี Node.js LTS (ติดตั้งแล้วด้วย `winget install OpenJS.NodeJS.LTS`) จากนั้น `npm install` ครั้งเดียว

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run serve` | เซิร์ฟเวอร์ static ไม่พึ่งแพ็กเกจ (พอร์ต 5173 หรือ `node scripts/serve.mjs 8080`) |
| `npm test` | Playwright บน Edge ที่มีในเครื่อง: รันชุดทดสอบทั้งหมดของ `tests/index.html` + เปิดหน้าแรก/คู่มือเช็ค console |
| `npm run test:cli` | ตัวรันเทสต์เดียวกันโดยไม่ต้องใช้ Node (PowerShell + Edge + jwebserver) ไว้ใช้บนเครื่องที่ไม่มี Node |
| `npm run lint` | ESLint (ตอนนี้ 0 error, 8 คำเตือนตัวแปรไม่ได้ใช้) |
| `npm run format:check` | Prettier ตรวจรูปแบบ (ยังไม่เคยรัน `format` กับโค้ดเดิม เพราะจะเปลี่ยนทุกไฟล์ในครั้งเดียว) |

`npm test` รันทั้ง Edge (Chromium) และ WebKit (ใกล้เคียง Safari) ถ้าจะเพิ่ม Firefox: `npx playwright install firefox` แล้วเพิ่ม project ใน `playwright.config.mjs`

Supabase CLI ติดตั้งเป็น devDependency แล้ว (`npx supabase --version`) ยังไม่ได้ `supabase init` / login / เชื่อมโปรเจกต์ ต้องมีโปรเจกต์ Supabase ของคุณก่อน

### โหมดออนไลน์ (Supabase)

แอปทำงานได้สองโหมด โหมดออนไลน์เปิดเองเมื่อมี `js/vendor/supabase.js` + `js/remote.js` และ `supabase` ใน `js/config.js` (ค่าเริ่มต้นของแอปที่ deploy)

| | ออนไลน์ (ปกติ) | ในเครื่อง (`?local=1`, ชุดทดสอบ, `?ns=`) |
|---|---|---|
| บัญชี | Supabase Auth (อีเมล + รหัสผ่าน) | เก็บใน localStorage |
| ข้อมูล | ฐานข้อมูล Supabase + cache ในเครื่อง ซิงก์เบื้องหลังส่งเฉพาะแถวที่เปลี่ยน | localStorage |
| ลืมรหัสผ่าน | ลิงก์ทางอีเมล | รหัสกู้คืน |

- `js/remote.js` เป็นชั้นเดียวที่คุยกับ Supabase (ล็อกอิน โหลดข้อมูล ซิงก์) `store.js` ยังทำงานแบบเดิมในหน่วยความจำ หน้าจอจึงไม่ต้องรอเครือข่าย
- ซิงก์ไม่สำเร็จ (เช่น ออฟไลน์) ข้อมูลยังอยู่ในเครื่องและลองใหม่เอง เปิดแอปครั้งหน้าส่วนที่ค้างจะถูกส่งขึ้นก่อน
- ออกจากระบบ: ส่งส่วนที่ค้างให้จบก่อน แล้วลบ cache ในเครื่อง (เครื่องที่ใช้ร่วมกัน)
- schema + RLS อยู่ใน `supabase/migrations/` ทดสอบ RLS ด้วย `npx supabase db query --linked -f supabase/tests/rls.sql` (จบด้วย `RLS_TEST_PASSED` เสมอ และ rollback)
- ตั้งค่า Auth (ปิดยืนยันอีเมล, URL ที่ลิงก์รีเซ็ตพากลับมา) อยู่ใน `supabase/config.toml` ส่งขึ้นโปรเจกต์ด้วย `npx supabase config diff` ดูผลต่าง แล้ว `npx supabase config push`
- เทสต์โหมดออนไลน์กับของจริง: `e2e/cloud-smoke.spec.mjs` (รันกับ `npm test` ปกติ ไม่สร้างบัญชี) และ `e2e/cloud.spec.mjs` (สมัคร→ซิงก์→ลบบัญชี รันเมื่อสั่ง `REDAY_E2E_CLOUD=1 npx playwright test e2e/cloud.spec.mjs`) ทดสอบเว็บที่ deploy แล้วด้วย `REDAY_BASE_URL=https://paratakorncsc13-a11y.github.io/Reday-pj/` (ลงท้ายด้วย `/`)

### จำลองเวลา (สำหรับสาธิต/ทดสอบ)

เปิด `http://localhost:5173/?now=2026-10-01T09:30:00%2B07:00` เพื่อให้แอปคิดว่าตอนนี้คือเวลานั้น (เวลาเดินต่อจากค่าที่ตั้ง) ใช้ทดสอบเส้นเวลาตัดวัน 04:00 น. หรือช่วงเย็นได้
